# ul-omo-webui 备份与恢复说明

本文描述部署形态下的全部状态所在与备份恢复步骤。环境变量语义以
`server/src/config.ts` 实现为准，此处列缺省值与覆盖变量。

## 发行形态（先读）

当前发行包是「单二进制 + 引擎闭包目录」的组合，不是绝对单文件：

```
发布目录/
  ul-omo-webui            单二进制（web 前端静态资产内嵌，宿主 JS 静态打包）
  engine/node_modules/   引擎运行时闭包（omo-ai + @code-yeongyu/senpi + senpi-codemode）
  data/                  运行数据目录（首次启动自动生成，见下节）
```

- 运行要求：PATH 上有 node。引擎是 spawn 出去的独立 node 子进程，其运行时
  文件无法静态编译进宿主二进制，因此随包附带 `engine/` 目录。
- 二进制可从任意目录启动（数据目录锚定在可执行文件旁，与 cwd 无关）。
- 备份/迁移二进制时应连同 `engine/` 一起带走（或在新机重新
  `bun run build:binary` 构建一份同版本产物）。

## 备份对象

全部状态 = DATA_DIR + 引擎会话库，两处都要备：

### 1. DATA_DIR（webui 运行数据）

缺省位置：可执行文件旁的 `data/` 目录（编译形态缺省；源码形态为
`server/data/`）。可用 `UL_OMO_WEBUI_DATA_DIR` 指到别处（如 home 下数据盘）。

| 文件 | 内容 | 权限 |
|---|---|---|
| `meta.db`（及 `-shm`/`-wal`） | SQLite 元数据库：项目、会话元数据（置顶/归档/重命名/未读/生成标题/标签挂载）、笔记（含回收站与版本历史）、草稿、输入历史、设置 kv（外链 URL 等；项目偏好与权限预设已迁项目配置文件） | 0644 |
| `password` | 登录密码（`UL_OMO_WEBUI_PASSWORD` 未设置时首次启动生成并写入） | 0600 |
| `session-secret` | 会话 cookie 的 HMAC 签名密钥（删除它 = 全部已发会话立即失效） | 0600 |
| `engine-processes.json` | 引擎子进程 PID 登记表（孤儿清扫的跨重启记录，可再生） | 0644 |

备份方式：停服后整目录拷走（WAL 模式下运行中拷贝 `meta.db` 可能拿到
不一致快照；不停服则用 `sqlite3 meta.db ".backup 备份路径.db"`）。注意
`password` 与 `session-secret` 是敏感凭据，备份介质要按口令同等对待。

### 2. 引擎会话库（会话正文）

会话的对话内容（jsonl 文件）不在 DATA_DIR，而在引擎 agent 目录下：

- 缺省位置：`~/.pi/agent/sessions/`，可用 `UL_OMO_WEBUI_AGENT_DIR` 覆盖。
- 布局：`sessions/<cwd 编码目录>/<时间戳>_<sessionId>.jsonl`，旁边还有
  `auth.json`（引擎凭证）、`models-store.json`（模型目录）等。
- webui 对该目录是零拷贝只读复用：web 端与终端 omo TUI 共用同一份会话。

备份方式：整目录拷贝。若同一 agent 目录还服务终端 omo，备份它等于同时
备份终端侧的会话历史；反过来删它两端一起丢。`auth.json` 是可执行任意
命令的引擎凭证，敏感级别同 DATA_DIR 里的凭据文件。

### 3. 配置文件（标签与常用语定义）

标签与常用语的**定义**不在 DATA_DIR，备份 DATA_DIR 不包含它们：

- 全局定义在 `~/.config/ul-omo-webui/`（`tags.json` / `snippets.json`，
  目录位置可用 `UL_OMO_WEBUI_CONFIG_DIR` 改）：该目录本身建议纳入 git
  管理，git 仓库即备份，新机 clone 即恢复。
- 项目级定义在各项目根 `.ul-omo-webui.json`（项目级标签、常用语、
  preferredModel、permissionPreset）：项目仓库即备份，随项目一同
  提交推送即可。

会话与标签的**挂载关系**（哪个会话挂了哪些标签）在 meta.db，随第 1 节
一起备份。定义丢了挂载还在（表现为孤儿标签），反过来同理，两处都要顾。

> 汇总：**备份 DATA_DIR + agentDir/sessions + 两类配置文件（全局配置
> 目录的 git 仓库与各项目仓库）即全部状态。** DATA_DIR 丢了会丢元数据
> （置顶/草稿/历史/笔记/标签挂载/生成标题/设置）与登录凭据；sessions
> 丢了会丢对话正文；配置文件丢了会丢标签与常用语定义。合起来才能完整
> 恢复。

## 恢复步骤

1. 在新机/新目录放好发行包（`ul-omo-webui` + `engine/`），确认 PATH 上有 node。
2. 还原 DATA_DIR 到可执行文件旁 `data/`（或设 `UL_OMO_WEBUI_DATA_DIR` 指向
   还原位置）。
3. 还原引擎会话库到 `~/.pi/agent/`（或设 `UL_OMO_WEBUI_AGENT_DIR` 指向还原
   位置）。若只还原了 `sessions/` 子集，缺少的会话在列表里自然缺席，不报错。
4. 还原配置文件：全局配置目录按其 git 仓库 clone/checkout 到
   `~/.config/ul-omo-webui/`（或设 `UL_OMO_WEBUI_CONFIG_DIR`）；各项目的
   `.ul-omo-webui.json` 随项目仓库 checkout。
5. 启动 `./ul-omo-webui`。密码读取 `data/password`，会话 cookie 用
   `data/session-secret` 验签——两文件齐全时旧密码与已发 cookie 仍有效；
   只缺 session-secret 时所有旧会话登录态失效（重新登录即可）。
6. 打开页面核对：项目列表、会话列表、点开旧会话正文完整、标签与笔记在
   即恢复成功。

## 与外链工具的关系

cgit / filebrowser 是独立自托管工具（部署参考见同目录 compose 示例），
它们的状态（filebrowser 的账号库等）按各自工具的备份口径处理，不在
ul-omo-webui 备份范围内。
