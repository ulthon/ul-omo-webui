# 产品待办与功能设想（用户提出，持续入账）

> 本文档记录功能设想与落地状态。每项标状态：`设想`（用户口头描述）/ `讨论中`（方案已给待拍板）/ `已拍板`（可开工）/ `已实施`（已落地，附实施日期与实际方案）。
> 用户会持续补充细节优化，新条目追加在对应分区，不删旧条目。

## 一、已提出的功能设想

### P1 会话标签（状态：已实施 2026-10-11）

- 需求：给会话打**自定义标签**，标签**云端同步**
- 产品意义：会话数量多以后，用标签记录每个会话的大体进度/状态，一眼分类
- 用户示例标签（工作流状态向）：研究阶段、制定计划、准备执行计划、高精度执行、审查、准备执行……
- 待澄清（讨论时问）：
  - "云端同步"指多设备经自托管服务器同步（现有单实例架构天然满足），还是接入外部云服务（新增依赖，需重新讨论形态）
  - 标签作用域：全局标签库 vs 按项目独立
  - 是否按标签过滤/搜索会话列表
- 实际方案（2026-10-11）：
  - 作用域两级并存：全局标签集（`~/.config/senpi-webui/tags.json`）与项目级标签集（项目根 `.senpi-webui.json`），均为文本文件
  - 会话与标签多对多：一个会话可挂多个标签（复选式打标，行内徽标、批量打标），挂载关系存 meta 库
  - 过滤为 OR 语义：多选标签时任一命中即显示；孤儿挂载（定义已删）灰显可单点清理
  - "同步"落地为 git 文件同步：全局定义进用户配置 git 仓库，项目级随项目仓库，多机 clone/pull 即同步；无外部云服务

### P2 项目笔记（状态：已实施 2026-10-11）

- 需求：按项目记录**纯文本笔记**，云端同步，方便查看
- 产品意义：项目有很多固定信息（运行环境、临时密码等），需要人为记录管理；给**使用者**用，不给智能体用
- 笔记本身要支持标签分类，用户示例：环境、想法、下一步计划
- **兜底存储（硬要求）**：用户可随意改、随意删，最终都有办法找回
  - 需要回收站（软删除）
  - 需要变更记录（历史版本可回看/恢复）
- 待澄清：纯文本是否要极简 markdown 支持；单条笔记长度上限预期
- 实际方案（2026-10-11）：
  - 主区"笔记"页签，markdown 渲染，笔记自带标签分类；未注入 prompt，不给智能体用
  - 存储在 meta 库（单机运行数据，随 DATA_DIR 备份），未做成文件配置形态
  - 兜底硬要求兑现：删除即软删进回收站（可恢复/彻底删除），内容有变化才产生版本，历史版本可回看与恢复
  - 单条正文上限 64KB；离开编辑态有未保存提示（页签切换与页面刷新两条路径）

### P3 会话列表全局化 + 最近会话（状态：已实施 2026-10-11，2026-10-11 提出）

- 需求：参考 OpenChamber 的组织方式，用户明确表示更喜欢那种
  - 现状：左上角项目切换器 → 侧栏仅显示当前项目的会话
  - 期望：左侧直接平铺**所有项目**的会话（项目作为分组头），不用切来切去
  - 期望：**最近会话**功能（跨项目按最近活动聚合的快捷入口，OpenChamber 有而本产品无）
- 待澄清（讨论时问）：
  - 项目切换器去留（可能转为过滤入口或移入设置）
  - 搜索语义是否随之为全局搜索（现为项目内标题搜索）
  - 「最近会话」形态：独立置顶区？数量上限？与现有置顶/未读角标的关系
  - 全量平铺后的列表性能与折叠记忆（长列表实测 1075 会话无长任务，但分组结构需交互设计）
- 实际方案（2026-10-11）：
  - 侧栏平铺全部注册项目的会话，项目作分组头；分组可折叠，展开记忆存 localStorage，当前项目组默认展开
  - 最近会话：独立置顶区，跨项目按最近活动取 8 条，点击直达（跨项目自动切换并应用目标项目偏好模型）；置顶/未读角标照常显示
  - 项目切换器保留在顶栏，新增"定位"能力（展开侧栏对应分组并滚动置顶）；跨项目点击会话直接切换，不必先切项目
  - 搜索仍为标题级子串，全局视图下作用于全部项目

### P4 添加项目的目录浏览选择（状态：已实施 2026-10-11，2026-10-11 提出）

- 需求：创建项目时不只能手动输入路径，要能**按磁盘实际目录结构浏览选择**
- 现状事实：设置面板添加项目仅一个路径输入框（错误路径有报错提示）；文件浏览接口 /api/fs/tree 仅对已注册项目内开放，添加时无浏览能力
- 候选方案（讨论时选）：
  - A 目录树选择器：弹窗内树形懒加载展开（复用 fs/tree 交互模式，需新的受限浏览端点）
  - B 输入框自动补全：输入路径前缀时提示下一级子目录（轻量）
  - 两者可并存
- 待澄清（讨论时问）：
  - 浏览起点与范围（home？根？上次选择目录？）——注意浏览端点需限定范围，避免无意的全盘任意列目录（单用户自托管风险可控，但设计上要有边界）
  - 是否需要搜索/收藏常用目录
  - 手动粘贴路径入口保留
- 实际方案（2026-10-11）：
  - 方案 A+B 并存：输入框自动补全（停顿 300ms 提示下一级子目录，键盘上下选择或点选回填）+"浏览…"按钮目录树弹窗（懒加载逐级展开，选中高亮后确认回填）
  - 新增受限浏览端点 /api/fs/browse，浏览严格限定 home 目录内（服务端逐请求校验，越界 403）
  - 手动粘贴路径入口保留且优先可见，提交仍走既有服务端校验

### P5 常用语（状态：已实施 2026-10-11；来源：用户随本轮七项功能升级追加，2026-10-11 随计划拍板）

- 需求：把常用的话存成条目，一键插入或直接发送，手机上少打字
- 实际方案（2026-10-11）：
  - 两级作用域：全局集（`~/.config/senpi-webui/snippets.json`）与项目级集（项目根 `.senpi-webui.json`），均为文本文件，随 git 同步
  - 面板点条目 = 插入输入框（走草稿链路，光标落条目末尾）；条目上发送按钮 = 直接发送该条目文本（不掺输入框现有内容，也不清空现有草稿/图片/历史条）
  - 管理弹层：增删改、上移下移排序、从输入历史导入（超单条上限的历史条目禁选）；单条上限 4KB

## 二、讨论中待拍板（方案已给，等用户选）

### D1 会话标题生成（状态：已实施 2026-10-11，2026-10-11 讨论）

- 现状事实：引擎不生成标题，现回退链 = 手动改名 > 引擎 name（该引擎线恒为空）> 首条消息截断 80 字 > "(空会话)"
- 方案：A 自动生成（首回合结束后调 flash 模型总结 ≤16 字）/ B 手动"生成标题"菜单项 / C 两者都要（推荐）
- 边界约定（若选 C）：自动生成仅对无标题会话生效一次；手动改名永远优先；重新生成可强制覆盖
- 实际方案（2026-10-11，方案 C）：
  - 自动：首回合结束后服务端静默调模型生成 ≤16 字中文短标题，仅对无标题会话生效一次；手动改名永远优先（标题链结构保证）
  - 手动：会话菜单"生成标题"，写入手动改名字段，可对已有标题强制重新生成
  - 完整优先级链：手动改名 > 引擎 name > 生成标题 > 首条消息截断 > "(空会话)"
  - 调用凭证复用引擎 agent 目录的 auth.json；端点与模型可用环境变量覆盖：`SENPI_WEBUI_TITLE_BASEURL` / `SENPI_WEBUI_TITLE_MODEL`（缺省 zai coding 端点 + glm-5.3-flash）

### D2 手机端输入区重设计（状态：已实施 2026-10-11，方向 2；2026-10-11 讨论，现状截图已发邮箱）

- 实测问题：输入框仅占屏宽 55-60%（左侧撤销/@/附件三钮约 130px + 右侧发送键挤压）；多行每行仅容 12-14 汉字；底部安全区内边距不足；发送键视觉比重过大
- 方向：1 按钮折叠为"+"（保守）/ 2 输入框整行在上+工具条在下（现代 chat 风格，推荐）/ 3 图标内嵌输入框内
- 安全区 padding 随所选方案一并修
- 实际方案（2026-10-11，方向 2）：
  - 输入框整行在上（自适应增高），工具条行在下：左侧输入历史、@ 引用、图片、常用语四钮，右侧发送钮
  - 390 屏输入框宽度占比从约 55% 提到实测 93.8%，单行汉字容量 9 → 24
  - 底部安全区 padding 修正；键盘弹出经 visualViewport 自适应，输入区保持完整可见不被遮挡
  - 发送钮降为描边样式（可发送时填充），视觉比重回落
