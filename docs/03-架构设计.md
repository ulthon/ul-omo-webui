# 架构设计

## 总体架构

```
手机/桌面浏览器 (React SPA, 响应式)
  ├─ 会话列表（常驻侧栏 / 手机抽屉）
  ├─ 对话流（AgentSessionEvent 渲染）
  ├─ 权限确认卡片（extension_ui_request → web 表单 → response）
  ├─ 文件树 + 只读预览 + @引用进对话
  └─ 未提交变更页签（git status/diff 只读）
       ↕ HTTPS: REST（上行）+ SSE（下行事件流）
宿主 server（Bun 单进程）
  ├─ 引擎子进程管理：per-project spawn `senpi --mode rpc`，重启/空闲回收
  ├─ EngineAdapter（见下）
  ├─ 事件桥：引擎事件 → SSE 流
  ├─ REST：会话/消息/prompt/abort/权限应答/项目/元数据
  ├─ 元数据 sqlite：置顶/排序/归档/项目/草稿/输入历史
  ├─ host tools（可选二期）：把浏览器能力注入给 agent
  └─ 静态文件托管 + 单用户密码
引擎：senpi（MIT）+ omo 扩展（omo-ai 安装）
外链：/git → cgit 或 Gitea；/files → filebrowser（docker，caddy 按路径反代）
```

## EngineAdapter —— 唯一需要"多想一步"的抽象

```
EngineAdapter（自定薄接口）
  sessions.list / messages / prompt / abort
  events() → SSE
  permission.respond()
  agents.list / models.list
  todo 状态 / usage 统计 / 图片 part
        │
        ├── SenpiAdapter    ← 首选：spawn senpi --mode rpc + 官方 RpcClient
        └── OpencodeV2Adapter（备用：@opencode/client，OpenChamber 同款路径）
```

- 抽象不做深，但接口边界第一天留好：换引擎、甚至双引擎并存，都是加一个 adapter 的事
- docs/06 的验证清单就是照着这个接口逐条验收的

## 数据一致性模型（本架构最重要的保证）

宿主 spawn 引擎子进程时，必须继承正确的 HOME 与项目 cwd（及环境变量）。做到这一点，对引擎来说 web 会话和终端会话没有任何区别：

| 数据 | 存储位置 | 一致性 |
|---|---|---|
| 会话本体（对话/工具调用/todo/token） | 引擎 session store（senpi sqlite） | 同一份；TUI 与 web 互相可见、互相恢复 |
| agent 定义、skills、规则、AGENTS.md | 文件系统（~/.senpi/、~/.omo/、项目内 .omo/、AGENTS.md） | 同一份 |
| 模型凭证 | 同一 HOME 下的引擎 auth 存储 | 同一份，登录一次两端可用 |
| 工作产出（代码/git 仓库） | 项目工作目录 | 本来就同一目录 |
| 置顶/排序/归档/草稿/输入历史 | 壳层自有 sqlite | 纯增量，TUI 无此概念，不冲突 |

## 并发边界（诚实约束）

- 两端**看**同一历史会话：没问题
- 同一"正在跑"的会话不建议两端同时**驾驶**：引擎对跨进程同一会话有占用/锁语义，具体行为待实测（docs/06）
- 正在跑的会话在哪个前端开的就在哪个前端看；两端都能看到它的存在与进度，只是别两边同时输入

## 元数据"云端"语义

单用户自托管：所有设备访问同一个 server，置顶/排序/项目配置存服务端 sqlite，天然跨设备一致，不需要账号/云服务/同步机制。"云端"就是那台 server。

边界：不做多实例聚合（已明确不做）；公司/家里两台机器的场景用远程访问一台中心 server 解决（隧道一条命令）。
