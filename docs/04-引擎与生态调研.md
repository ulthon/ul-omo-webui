# 引擎与生态调研结论（2026-10 完成）

调研目的：为 web 工作台选定引擎与产品形态。以下为关键事实与结论，全部经过实物核验（npm 包类型定义、本地安装产物 grep、官方迁移文档、本机数据库），非记忆推测。

## 一、为什么是 senpi，而不是 opencode v2

### omo 的迁移事实

- omo（oh-my-openagent）5.x 已全线运行在 **senpi** 上：npm 包 `omo-ai`（latest 5.1.19），官方自述 senpi 是"基于 pi 的 fork"，独立命令 `omo`，不再加载进 opencode
- 演化链：pi（pi.dev，极简 agent harness，四模式：TUI/print/RPC/SDK）→ senpi（omo 团队 fork，补齐 server/protocol/client 远程三件套、sqlite 会话、扩展系统、PTY）→ omo-ai（senpi + omo 全套扩展的发行版）
- 许可：senpi 引擎 MIT（可自由使用）；omo 扩展本体 SUL-1.0（个人/内部使用、修改、免费分发均可，商用禁止）
- omo 官方自己在做 **senpi-desktop**（Electron 桌面方向），web 方向无公开动作——本项目的生态位

### opencode v2 结论（曾深入评估，未选）

- v2 全新 plugin API（Plugin.define + domain hooks/transforms），v1 插件完全不加载；omo 用的 v1 扩展点约 95% 在 v2 有官方映射，做 v2 版 omo 可行但已无必要——omo 主力已离开 opencode
- v2 是 server-first 架构 + @opencode/client，OpenChamber 证明了 web 前端全功能可行
- 结论：作为 EngineAdapter 的备用实现保留（OpencodeV2Adapter），不作为首选引擎

### senpi RPC 对宿主的关键能力（pi/senpi 把"做宿主"设计成一等公民）

- RPC 模式：stdio JSONL 协议，官方 TS/Python RpcClient
- **host tools**：宿主给 agent 注入自定义工具（web 端可注入浏览器能力）
- **host URI schemes**：宿主拥有虚拟文件系统
- **extension UI 往返**：select/confirm/input/editor 请求转发宿主渲染——web 权限确认/表单应答的协议原生支持
- AgentSessionEvent 事件流、消息分页、subagent_lifecycle/progress/event 三种子代理事件流
- omo 扩展的 `omo.dag.event` 顺序账本 + `omo.task.updated` 快照推送（为外部 viewer 设计，web 编排可视化可吃）
- 附带发现：senpi 包还导出 `./client`（CBOR 远程会话客户端）和 `connectWebViewService`（webview 桥）——能力边界待验证（docs/06）

## 二、OpenChamber 摸底（对标物）

- MIT，11k+ stars，opencode 的多表面工作台（Desktop/Web-PWA/VSCode/移动/CLI-Server）
- **只支持 opencode 引擎**（@opencode-ai/sdk/v2），不支持 pi/senpi
- 架构参考价值：刚完成运行时解耦（RuntimeAPIs 抽象 + runtime switching）；git 服务（simple-git）、diff 渲染（web worker）、SSE 桥、多服务器聚合（SSE fan-in + 断路器）等模块设计可直接借鉴
- 功能上砍掉的：Multi-run、Session Goals、Changes Walkthrough、PR/GitHub 集成、E2EE Relay——本产品不做

## 三、竞品格局（2026-10）

同类"omo 平替/编排插件"已形成生态：oh-my-opencode-slim（MIT，双栈 v1+v2）、opencode-weave、opencode-senate、hiai-opencode、opencode-v2-agent-orchestrator、opencode-ensemble（v2 原生 team，worktree 隔离 + TUI companion via plugin RPC）、@malhashemi/opencode-dynamic-workflows（TS 工作流引擎 + web 面板）等。OCP（OpenCode Prime）是完整 v2 增强套件样例，公开了 15 条 v2 降级 GAP 清单（toast 无通知域等，可当踩坑地图）。

结论：**"senpi/omo 的 web 工作台"位置是空的**——OpenChamber 只吃 opencode，omo 官方在做桌面不做 web，竞品全是终端插件形态。

## 四、本项目不做编排可视化的决策

最初曾设想把 omo 的 DAG/team 可视化作为差异化核心，后经用户收缩需求：功能集对标 opencode v1 TUI 即可。因此 MVP 不含 DAG 图；但 subagent 事件流与 omo.dag.event 通道的存在意味着将来要做随时可加（记录于此，防止丢失这条路径）。
