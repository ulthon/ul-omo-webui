# 自启动与更新（立项文档，2026-10-19）

> 状态：已拍板待实施（决策四项 + 引擎更新方案 B + Windows 形态假设，均见"决策记录"）。
> 背景：对标 openchamber 的 `startup enable` 机制（systemd/launchd/计划任务 + 环境快照）与 npm 全局包更新链路。

## 一、目标

1. 支持 Linux（systemd --user）与 Windows（计划任务）开机/登录自动启动 webui 服务。
2. 支持两层更新检测与手动确认更新：
   - webui 层：本地版本 vs npm registry `@ulthon/ul-omo-webui` 最新版
   - omo 引擎层：本地 `omo-ai`/`senpi` 版本 vs registry 最新版
3. 更新执行后服务自愈拉起（依赖服务管理器的 Restart 策略）。

## 二、非目标（第一版不做）

- 静默自动更新（只做检测+手动确认）
- macOS launchd 支持（结构预留，后补）
- WSL 形态的 Windows 支持（第一版仅支持原生 Node 全局安装；见决策 D6）
- git 源码部署 / 单二进制分发形态的更新通道（仅 npm 全局形态）

## 四、里程碑拆分与验收标准

### M1 自启动（CLI）——已实施 2026-10-19（Windows 真机验收待补）

- 内容：CLI 子命令 `ul-omo-webui startup enable|disable|status`
  - Linux：生成 `~/.config/systemd/user/senpi-webui.service`，`systemctl --user enable --now`，必要时 `loginctl enable-linger`
  - Windows：`schtasks /create` 登录时启动任务，指向全局 bin 入口
  - 环境变量快照写入服务定义（D5）
- 验收：
  - Linux：重启机器后不登录，服务自动监听 0.0.0.0:7788
  - Windows：注销重登后进程自动运行
  - `disable` 后重启不再拉起；`status` 输出服务状态
  - 服务崩溃后自动重启（Restart 策略生效）

### M2 更新检测与 UI 提示

- 内容：
  - server 端 API：查询本地版本（webui / omo-ai / senpi）与 registry 最新版，返回是否有新版
  - web UI：设置/状态区展示两层版本信息与"有新版"提示
- 验收：
  - registry 有新版本号时 UI 出现提示；无更新时不出现
  - 检测失败（离线/registry 不可达）静默降级为"未知"，不报错弹窗
  - 不做任何自动下载

### M3 更新执行与自重启

- 内容：
  - 确认按钮触发 server 端执行 `npm install -g @ulthon/ul-omo-webui@latest`（方案 B：webui 与引擎更新执行合并为这一次重装）
  - 执行完成后服务优雅退出，由 systemd/计划任务 Restart 拉起新版本
  - 更新过程 UI 可见进度/结果；失败时保留旧版本可运行状态（npm 重装失败不影响已装版本）
- 验收：
  - 手动发一个测试新版本到 registry，从 UI 确认到新版本运行的完整链路走通（Linux 与 Windows 各一遍）
  - 更新中途 kill 更新进程，服务仍以旧版本运行，可再次发起更新
  - 更新完成后 UI 显示新版本号

### M4 文档

- 内容：README/使用文档补 startup 用法、环境变量快照说明、更新机制说明
- 验收：新用户仅凭文档可在 Linux/Windows 完成自启动配置

- Linux 验收已在本机实证：enable 后服务 active 且 HTTP 200；kill -9 后 3 秒自动拉起恢复 200；disable 后服务移除不再拉起。Windows 仅过生成逻辑单测（schtasks 装配、包装脚本快照/重启循环），真机验收待 Windows 环境执行。
- 实现入口：`server/src/cli.ts`（参数分发）+ `server/src/startup.ts`（双平台实现），构建入口由 index.ts 改为 cli.ts（bin 路径不变）。新增 `server/test/startup.test.ts` 6 例。

## 五、风险与边界情况

- npm 全局重装期间旧进程继续运行，Windows 上文件占用可能导致重装失败——需实测，必要时先停服务再装（由更新执行器编排）。
- 引擎大版本升级可能带来行为变化——UI 确认文案中展示目标版本号，由用户自行判断。
- systemd --user 需要 linger 才能不登录常驻，文档必须写明。
