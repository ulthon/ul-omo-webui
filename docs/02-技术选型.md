# 技术选型

总原则：TypeScript 单语言全栈、与引擎同栈（senpi 生态是 TS + Bun）、一切从薄。这个产品本质是"事件桥 + 壳"，技术选择都服务于这一点。

## 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言/运行时 | TypeScript + Bun | senpi/omo 生态原生 Bun；宿主 server 很薄，一个运行时通吃前后端脚本；`bun compile` 可打成单可执行文件分发（omo 自己就这么分发 12 个平台二进制，路被验证过）。兼容性问题退路是 Node |
| 后端框架 | Hono | 薄、快、TS 原生、跑 Bun/Node 都行。server 只需要 REST + SSE + 静态托管 |
| 通信 | REST（上行）+ SSE（下行事件流） | 下行全是服务端推（对话流/状态/权限请求）；上行动作全是简单 POST。不做 WebSocket（终端已砍，SSE 够用且省连接状态机） |
| 前端框架 | React + Vite，纯 SPA | 组件生态最全；OpenChamber 的 UI 是 React + MIT，参考/借用同栈成本最低；不做 SSR/Next（私人数据自托管，SSR 零收益） |
| 状态管理 | Zustand | 订阅粒度到单条消息 part：流式 delta 只重渲染单个气泡，列表不动 |
| Markdown/高亮 | react-markdown + Shiki（web worker 内） | Shiki 渲染质量天花板，OpenChamber 同款；worker 不卡主线程（手机端重要） |
| Diff 视图 | react-diff-view | 未提交变更页签与工具卡片 diff 共用 |
| 虚拟列表 | TanStack Virtual | 长会话手机端不卡 |
| 样式/组件 | Tailwind + shadcn/ui | 到此为止，不引入更重的框架 |
| 元数据库 | SQLite（bun:sqlite，单文件） | 置顶/排序/归档/项目/草稿/输入历史全放这里；零运维；将来会话标题全文搜索也是它 |
| 引擎对接 | senpi 官方 RpcClient，外包一层自定 EngineAdapter 接口 | 见 docs/03 |

## 部署形态

```
服务器上：
  主服务    → bun compile 出的单可执行（内嵌前端静态资源），监听 localhost
  Caddy     → 反代 + 自动 HTTPS，路径分发：
              /      主服务
              /git   cgit（docker）
              /files filebrowser（docker，按需）
```

- 外链工具用 docker compose 编排；主服务不进容器（单二进制直接跑）
- 单用户密码鉴权（中间件几行），无账号系统
- 数据备份 = 拷 sqlite 文件 + 引擎会话库
