# 数据层实证：本机 opencode 数据库分析

2026-10-06 对本机 `~/.local/share/opencode/`（opencode v1.18.34 + omo）的实际分析。这是 opencode v1 的数据模型，不是 senpi 的；senpi 的会话库结构需要实施时另行核对（见 docs/06）。此文档的价值：作为**产品行为的参照系**——会话列表、项目管理、usage 统计在成熟引擎里长什么样，senpi 应具备对等能力。

## 目录结构

```
~/.local/share/opencode/
  opencode.db          # 主库，本机 3.4GB（含 WAL 73MB）
  auth.json            # 凭证
  storage/             # omo 的键值存储（session_diff、directory-readme 等）
  snapshot/            # 文件快照（undo 用）
  tool-output/         # 大工具输出落盘
  repos/, log/
```

## 表结构要点（17 张表）

- **project**：一个项目 = 一个工作目录一条记录。字段：worktree 路径、vcs、name（本机全空——项目名不存库，展示时从路径推导）、图标、时间戳。本机 6 个项目（/data/projects/* 等）
- **project_directory**：多目录可映射同一项目（worktree 场景），本机 8 行对 6 项目
- **session**（本机 2107 条）：project_id 外键挂靠；关键字段：title、agent、model、directory、parent_id（子会话标记）、time_archived（归档）、cost、tokens_input/output/reasoning/cache_read/cache_write（五种 token 计数）、summary_files/additions/deletions（会话级变更统计）、share_url、revert
- message（6.1万）/ part（26万）/ todo（3994）/ event（85万，全量持久化）/ permission / credential / session_share

## 对产品设计的三个实证结论

1. **93% 是子会话**：2107 个会话中 1960 个带 parent_id（agent 自己创建），人工会话仅 147 个。会话列表必须分层：默认只显示人工会话；子会话按父会话折叠钻取（parent_id + agent 字段现成，标题形如"F2 代码质量审查 (@oracle subagent)"自带说明）；另给按项目过滤的"全部活动"视图。平铺子会话会淹没列表。
2. **归档字段原生有但从未使用**（time_archived 全 0）——TUI 没给归档入口。web 版做归档/置顶是补缺，不是锦上添花。
3. **token/费用/变更摘要直接在 session 行上**——底部状态条与列表"变更摘要"列零成本。另：本机 3.4GB 未清理的库也侧面说明列表搜索/归档/清理工具的必要。

## 与 web 版的关系

web 版会话列表/项目列表/usage 的产品行为以此库为参照验收：第一天上线即应完整展示引擎会话库的全部历史（本机 opencode 版如此，senpi 版需在实施时验证其 session store 的对等查询能力）。
